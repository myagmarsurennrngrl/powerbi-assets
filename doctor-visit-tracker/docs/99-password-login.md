# 99 — Нууц үгээр нэвтрэх (email + password)

**Юу өөрчлөгдсөн:** нэвтрэх арга нь и-мэйлээр ирдэг нэг удаагийн кодоос
**и-мэйл + нууц үг** болж сольсон.

**Хэн шийдсэн:** төслийн эзэн, 2026-07-28.

---

## 1. Яагаад сольсон

Нэг удаагийн код нь илүү сайн арга. Хулгайлах нууц үг байхгүй, мартах зүйл
байхгүй, сэргээх урсгал байхгүй. Гэхдээ **захидал нь хүрдэггүй байсан**:

| Саад | Тайлбар |
|---|---|
| Загвар нь код биш, холбоос илгээдэг | Supabase-ийн бэлэн загвар вэб сайтад зориулагдсан. Утасны апп холбоосыг ашиглаж чадахгүй. |
| Загварыг засахад SMTP шаардана | Үнэгүй багц дээр *"Set up custom SMTP to edit their subject and body"* гэж хаадаг. |
| SMTP тохируулахад IT шаардана | `monos.mn` бол байгууллагын домэйн. Microsoft 365 дээр SMTP AUTH анхдагчаар хаалттай. |
| Цагт 2 захидлын хязгаар | Төсөл дээр нийтдээ. 11 хүн ажиллах боломжгүй. |
| Байгууллагын шүүлтүүр | Ирсэн ч Microsoft Defender карантинд авдаг. |

Эдгээрийн нэг ч нь аппын алдаа биш. Гэхдээ нийлээд **нэвтрэх боломжгүй**
болгосон. Нууц үг нь и-мэйлээс огт хамаардаггүй тул энэ бүх гинжийг тайлдаг.

---

## 2. Юуг алдсан — шударгаар

Энэ нь үнэгүй биш. Гурван зүйлийг алдсан:

### 2.1 «Нууц үг мартсан» гэдгийг өөрөө сэргээх боломжгүй

Нууц үг сэргээхэд и-мэйл хэрэгтэй, и-мэйл ажиллахгүй. Тиймээс:

> Нууц үг мартвал **администратор шинийг олгоно**. `npm run dev:set-password`.

Аппын нэвтрэх дэлгэц дээр «Нууц үгээ мартсан бол?» гэсэн товч байгаа боловч тэр
нь **тайлбар харуулдаг, сэргээх хүсэлт илгээдэггүй**. Ажиллахгүй товч тавихаас
энэ нь дээр.

### 2.2 Хүн өөрөө бүртгүүлэх боломжгүй

Энэ нь хамгийн чухал шийдвэр. Хэрэв хүн бүр өөрөө бүртгүүлж нууц үг тавьж
чаддаг байсан бол:

> Ажилтан `darga@monos.mn` хаягаар дарга нь бүртгүүлэхээс **өмнө** бүртгүүлж,
> өөрийн нууц үг тавиад, даргын эрхээр багийн бүх өгөгдлийг үзэх боломжтой
> болно.

Нэг удаагийн кодтой үед энэ боломжгүй байсан: шуудангийн хайрцгийг эзэмших нь
өөрөө баталгаа байсан. И-мэйл ажиллахгүй тул тэр баталгаа алга болсон.

**Тиймээс: эхний нууц үгийг администратор олгоно.** Хүн нэвтрээд **Тохиргоо →
Нууц үг солих** дээрээс өөрийн нууц үг болгож солино. Ингэснээр:

- хэн ч бусдын хаягийг эзэмдэж чадахгүй — администраторын оролцоо шаардана
- хүн бүр өөрийн зохиосон нууц үгээ хэрэглэнэ

### 2.3 Хулгайлах зүйл байгаа болсон

Кодтой үед хулгайлах байнгын нууц байгаагүй. Одоо байна. Хамгаалалт:

- `monos.mn` домэйн хязгаарлалт хэвээрээ (migration 0006, өгөгдлийн санд хүчинтэй)
- дор хаяж 10 тэмдэгт (`src/domain/password.ts`)
- сесс нь `expo-secure-store` дотор, утасны хамгаалагдсан хэсэгт
- аудитын бүртгэл хэвээрээ — хэн юу хийснийг бүртгэсээр байна

## 3. Нууц үгийн дүрэм

`src/domain/password.ts` дотор, тестүүдтэй.

| Дүрэм | Утга |
|---|---|
| Дор хаяж **10 тэмдэгт** | Урт нь таамаглалыг хамгийн сайн хаадаг |
| Хамгийн ихдээ **72 байт** | bcrypt-ийн хязгаар. Кирилл үсэг 2 байт эзэлдэг тул ~36 кирилл тэмдэгт |
| И-мэйл хаягтайгаа адил байж болохгүй | |
| Нэг тэмдэгт дахин дахин болохгүй | `ааааааааааа` |
| Илэрхий сонголтууд болохгүй | `password12`, `monos2026`, `qwerty1234`, `эмч2026` |

**Том жижиг үсэг, тоо, тэмдэг хольж хутгах шаардлага байхгүй.** Тэр төрлийн
дүрэм нь `Password1!` гаргаад, монитор дээр наасан цаас үүсгэдэг. Урт нь л
чухал. Санахад хялбар 2–3 үг хамгийн зөв: `улаанбаатар-хавар-2026`.

## 4. Администраторын журам

### 4.1 Шинэ хүнд нууц үг олгох

```powershell
npm.cmd run dev:set-password
```

Асуух зүйлс: и-мэйл хаяг, шинэ нууц үг (2 удаа), `service_role` түлхүүр.
Дэлгэц дээр юу ч харагдахгүй, файлд юу ч бичигдэхгүй.

Дуусахад **нэг SQL мөр хэвлэнэ**. Түүнийг Supabase SQL Editor дээр ажиллуулна:

```sql
UPDATE public.app_user u
   SET auth_user_id = a.id
  FROM auth.users a
 WHERE lower(u.email::text) = lower('ner@monos.mn')
   AND lower(a.email) = lower(u.email::text)
   AND u.auth_user_id IS DISTINCT FROM a.id;
```

**Энэ мөрийг заавал ажиллуулна.** Үүнгүйгээр хүн нэвтэрч орох боловч
«Таны бүртгэл идэвхжээгүй байна» гэж заана — нэвтрэлт болсон ч аппын бүртгэл
холбогдоогүй учраас.

### 4.2 Нууц үгээ авсан хүнд юу хэлэх

> «Таны нэвтрэх нууц үг: `…`. Аппад нэвтэрсний дараа **Тохиргоо → Нууц үг
> солих** дээрээс өөрийн нууц үгээ тавина уу. Эхний нууц үгийг би мэдэж байгаа
> тул солих нь зөв.»

Эхний нууц үгийг **и-мэйлээр биш**, биечлэн эсвэл дуудлагаар дамжуулна.

### 4.3 Хуучин кодоор оролдсон бүртгэлүүд

Нэг удаагийн кодоор оролдож байсан хүмүүсийн `auth.users` бүртгэл нууц үггүй
байдаг. Ийм бүртгэлд нэвтрэх боломжгүй. `dev:set-password` нь эдгээрийг олж
нууц үг тохируулаад, и-мэйлийг «баталгаажсан» болгоно — тусад нь юу ч хийх
шаардлагагүй.

## 5. Supabase дээр шалгах тохиргоо

Authentication → **Sign In / Providers** → **Email**:

| Тохиргоо | Байх ёстой утга | Яагаад |
|---|---|---|
| Email provider | **Enabled** | |
| **Confirm email** | **Disabled** | Баталгаажуулах захидал ирдэггүй тул нээлттэй бол хэн ч нэвтэрч чадахгүй |
| Бусад бүх provider | **Disabled** | Нээлттэй байгаа бүхэн нь нэвтрэх өөр зам |

`Confirm email` нээлттэй үлдвэл шинэ бүртгэл баталгаажаагүй хэвээр байж,
нэвтрэхэд «И-мэйл хаяг эсвэл нууц үг буруу байна» гэж заана — нууц үг зөв
байсан ч. `dev:set-password` нь өөрөө баталгаажуулдаг тул түүгээр үүсгэсэн
бүртгэлүүд ажиллана, гэхдээ тохиргоог зөв болгосон нь дээр.

## 6. Ирээдүйд

### 6.1 SMTP тохируулсны дараа

Байгууллагын SMTP ажиллаж эхэлбэл:

- и-мэйлээр нууц үг сэргээх боломжтой болно (`AuthProvider` интерфейст зай
  байгаа)
- нэг удаагийн кодыг сонголт болгож эргүүлэн нэмж болно
- эхний нууц үгийг администратор олгох шаардлага байхгүй болно

Кодыг зориудаар ингэж бэлдсэн: `src/lib/auth/types.ts` дотор нэг ч
шийдвэрийг хатуу битүүмжлээгүй.

### 6.2 Microsoft Entra ID

Энэ өөрчлөлт **Entra ID рүү шилжих замд ямар ч сөрөг үр дагавар** үүсгээгүй:

- бүх дэлгэц `AuthProvider` интерфейсээс хамаардаг, Supabase-ээс биш
- `app_user.auth_user_id` нь өгөгдлийн сан дахь цорын ганц холбоос хэвээрээ
- Entra ID руу шилжихэд нууц үгийн функцууд шаардлагагүй болно (SSO ажиллана),
  интерфейсээс хасахад л хангалттай
