# Нэг хэрэглэгчээр бүх аппыг турших төлөвлөгөө

**Хэнд зориулсан:** аппыг анх удаа бүтнээр нь турших хүнд.
**Хугацаа:** 60–90 минут.
**Хэл:** энэ баримт монголоор. Аппын бүх бичвэр монголоор.

---

## Яагаад ийм өвөрмөц журам вэ

Гурван өөр эрхийг (төлөөлөгч / менежер / администратор) турших гэж гурван
хаягаар нэвтрэх шаардлагагүй. Эрхийг өгөгдлийн сан дээр солиод аппаа дахин
ачаалахад л хангалттай — §3, §4-т байгаа.

Сесс нь утсанд аюулгүй хадгалагдсан тул аппыг хааж нээхэд, утсаа унтрааж асаахад
ч алга болохгүй. **Гарах** товч дарвал нууц үгээ дахин оруулна — тэр нь одоо
асуудал биш, харин §0.3-д тавьсан нууц үгээ санаж байх хэрэгтэй.

---

## 0. Нэвтрэхээсээ ӨМНӨ бэлдэх

### 0.1 Өөрийн байршлаа олох

Утсан дээрээ Google Maps нээгээд байгаа газраа **удаан дараад** барина. Дээд
талд хоёр тоо гарч ирнэ, жишээ нь:

```
47.918700, 106.917700
```

Эхнийх нь **өргөрөг (latitude)**, хоёр дахь нь **уртраг (longitude)**. Хоёуланг
нь тэмдэглэж авна уу.

**Яагаад хэрэгтэй вэ:** уулзалт эхлүүлэхэд апп таныг эмнэлгийн 150 метрийн
дотор байгаа эсэхийг шалгадаг. Энэ шалгалт **серверт** хийгддэг тул утаснаас
хуурч болохгүй — зориудаар тэгж хийсэн. Тиймээс ажлын ширээнээсээ турших
цорын ганц зөв арга бол **эмнэлгийг түр таны байгаа цэг рүү зөөх** явдал.

### 0.2 Бэлтгэлийн скриптийг ажиллуулах

Supabase → **SQL Editor** → **New query**. Дараа нь төслийн
`supabase/test-setup-single-user.sql` файлыг бүтнээр нь хуулж наана.

Дээд талд нь **гурван утга засна**:

```sql
v_email text := 'myagmarsuren.na@monos.mn';   -- өөрийн ажлын и-мэйл
v_lat double precision := 47.918700;          -- 0.1-д олсон эхний тоо
v_lon double precision := 106.917700;         -- хоёр дахь тоо
```

**Run** дарна. Ийм хүснэгт гарч ирэх ёстой:

| status | step | detail |
|---|---|---|
| ✅ | 1. И-мэйлийн домэйн | … зөвшөөрөгдсөн. |
| ✅ | 2. Хуучин давхардсан бүртгэл | … |
| ✅ | 3. Туршилтын бүртгэл | rep01 (А. Ариунзаяа) → таны и-мэйл |
| ✅ | 4. Өнөөдрийн маршрут | Өнөөдөр хийх уулзалт байна. |
| ✅ | 5. Эмнэлгийн байршил | … хүрээг 2000 м болголоо. |
| ✅ | 6. ДҮГНЭЛТ | Бэлэн. |

**Хүснэгт огт хоосон гарвал** скрипт амжилтгүй болсон гэсэн үг. Улаан алдааны
бичвэрийг надад буулгаж өгнө үү — өгөгдлийн санд юу ч өөрчлөгдөөгүй байгаа.

Энэ скрипт юу хийдэг вэ: таны хаягийг үрийн өгөгдлийн `rep01` төлөөлөгчид
өгнө. Ингэснээр та хоосон апп руу биш, **4 долоо хоногийн төлөвлөгөө, хийсэн
уулзалтууд, KPI түүхтэй** орно. Мөн өнөөдөр хийх уулзалт байгаа эсэхийг
шалгаад, тэр уулзалтын эмнэлгийг таны байгаа цэг рүү зөөнө.

### 0.3 Өөртөө нууц үг олгох

Апп **и-мэйл + нууц үгээр** нэвтэрдэг. И-мэйл ирэхийг хүлээх зүйл байхгүй,
цагийн хязгаар ч байхгүй. Шалтгааныг `docs/99-password-login.md` дээр бичсэн.

Компьютер дээрээ, төслийн хавтаст:

```powershell
npm.cmd run dev:set-password
```

Асуух зүйлс:

1. И-мэйл хаяг — §0.2-т бичсэнтэй **яг ижил**
2. Шинэ нууц үг, 2 удаа — дор хаяж 10 тэмдэгт
3. `service_role` түлхүүр — Supabase → Settings → API → service_role → Copy

Нууц үг ч, түлхүүр ч дэлгэц дээр харагдахгүй, файлд ч бичигдэхгүй.

Дуусахад **нэг SQL мөр хэвлэнэ**. Түүнийг Supabase SQL Editor дээр ажиллуулна:

```sql
UPDATE public.app_user u
   SET auth_user_id = a.id
  FROM auth.users a
 WHERE lower(u.email::text) = lower('myagmarsuren.na@monos.mn')
   AND lower(a.email) = lower(u.email::text)
   AND u.auth_user_id IS DISTINCT FROM a.id;
```

> ⚠️ **Энэ мөрийг заавал ажиллуулна.** Үүнгүйгээр та нэвтэрч орох боловч
> «Таны бүртгэл идэвхжээгүй байна» гэж заана.

**Мөн Supabase дээр нэг тохиргоо шалгана.** Authentication → Sign In /
Providers → Email → **Confirm email** нь **унтраасан** байх ёстой. Нээлттэй
байвал баталгаажуулах захидал хүлээх болж, тэр захидал ирдэггүй.

### 0.4 Нэвтрэх боломжтой эсэхийг урьдчилан шалгах

Мөн SQL Editor дээр:

```sql
SELECT * FROM public.fn_diagnose_login('myagmarsuren.na@monos.mn');
```

6 мөр гарна. **Бүгд ✓ байх ёстой.** Ганц ✗ байвал тэр мөрийн `detail` баганад
яг юу хийхийг бичсэн байгаа. Нэвтрэхийг оролдохоос өмнө шалгаснаар цагаа
хэмнэнэ.

## 1. Нэвтрэх (5 минут)

Утсандаа Expo Go нээж QR уншуулна. Компьютер дээрээ эхлээд:

```powershell
npx.cmd expo start
```

1. И-мэйлээ бичнэ.
2. §0.3-д тавьсан нууц үгээ бичнэ.
3. **Нэвтрэх** дарна.

**Хүлээх үр дүн:** «Өнөөдрийн маршрут» дэлгэц нээгдэнэ.

Алдаа гарвал улаан талбарт **«Серверийн хариу»** гэсэн жижиг бичвэр гарна.
Түүнийг сонгоод хуулж надад илгээнэ үү — тэр бол алдааны жинхэнэ шалтгаан.

**Нэвтэрсний дараа шалгах зүйл:** Тохиргоо → **Нууц үг солих** ажиллаж байгаа
эсэх. Шинэ нууц үг тавиад, Гараад, шинэ нууц үгээрээ дахин нэвтэрч үзнэ үү —
одоо и-мэйл шаардахгүй тул гарахаас эмээх хэрэггүй.

---

## 2. Төлөөлөгчийн урсгал (30 минут)

Одоо та `representative` эрхтэй. Апп доод талдаа таб харуулна.

### 2.1 Өнөөдрийн маршрут

- [ ] Өнөөдөр хийх уулзалтууд жагсаалтаар харагдаж байна уу?
- [ ] Эмнэлгийн нэр, зорилго, дараалал зөв үү?

### 2.2 Уулзалт эхлүүлэх — GPS шалгалт

Жагсаалтаас **§0.2-д зөөсөн эмнэлгийг** сонгоод **Эхлүүлэх** дарна.

- [ ] Апп байршлын зөвшөөрөл асууна → **Зөвшөөрөх**.
- [ ] Зайг метрээр харуулна.
- [ ] Уулзалт эхэлж, цаг тоолж эхэлнэ.

**Хэрэв «Та эмнэлгээс хэтэрхий хол байна» гэвэл:** §0.1-д авсан тоонууд буруу,
эсвэл эхний ба хоёр дахь тоог сольж бичсэн байна. Скриптийг зөв тоогоор дахин
ажиллуулна.

**Санаатай шалгах зүйл:** энэ хориг серверт хийгддэг. Утасны байршлыг хуурамчаар
өөрчилж туршвал апп `is_mocked_location` гэж тэмдэглээд менежерт харуулна.

### 2.3 Тайлан бөглөх, дуусгах

- [ ] Уулзсан эмчээ сонгоно.
- [ ] Ярилцсан брэндээ сонгоно.
- [ ] Тэмдэглэл бичнэ.
- [ ] **Дуусгах** дарна → check-out байршил дахин бүртгэгдэнэ.

**Заавал шалгах:** тайланг хоосон орхиод дуусгах гэж үзнэ үү. Апп зөвшөөрөх
ёсгүй — энэ бол алдаа биш, зориудын шалгалт.

> 🔒 **Өвчтөний талаар ямар ч мэдээлэл оруулах талбар байх ёсгүй.** Хаа нэгтээ
> ийм талбар харвал надад заавал хэлнэ үү — энэ бол ноцтой зөрчил.

### 2.4 Залруулга (addendum)

Дууссан уулзалт руу орж **Залруулга нэмэх**.

- [ ] Нэмсэн залруулга харагдана.
- [ ] **Анхны тайлан хэвээрээ үлдсэн** — дарагдаагүй байх ёстой.

### 2.5 Төлөвлөгөөгүй уулзалт

- [ ] Нүүр → **Төлөвлөгөөгүй уулзалт**.
- [ ] Ойролцоох эмнэлгүүд зайгаараа эрэмбэлэгдэж харагдана.
- [ ] Шалтгаанаа бичээд эхлүүлнэ.

### 2.6 Хүсэлт (exception)

Өөр нэг уулзалт дээр **Хүсэлт илгээх** → «Эмч байхгүй байсан».

- [ ] Хүсэлт «Хүлээгдэж буй» төлөвт орно.
- [ ] **Та өөрөө зөвшөөрөх товч ХАРАГДАХГҮЙ байх ёстой.** Харагдвал надад хэлнэ үү.

### 2.7 Долоо хоногийн төлөвлөгөө

- [ ] Долоо хоног таб → 4 долоо хоног харагдана (өнгөрсөн 2, энэ, дараагийн).
- [ ] Дараа долоо хоногт уулзалт нэмж үзнэ.
- [ ] Баасан 18:00-аас хойш засах гэж үзвэл хаалттай байх ёстой.

### 2.8 KPI

- [ ] KPI таб → биелэлтийн хувь харагдана.
- [ ] §2.3-д дуусгасан уулзалт тоонд нэмэгдсэн үү?

### 2.9 Офлайн горим

**Хамгийн чухал шалгалт.** Утасны **нислэгийн горимыг асаана**.

- [ ] Уулзалт эхлүүлж, тайлан бөглөж, дуусгана.
- [ ] «Хадгалагдлаа, дараа илгээнэ» гэсэн мэдэгдэл гарна.
- [ ] Нүүр → **Синк** дэлгэц дээр хүлээгдэж буй ажил харагдана.
- [ ] Нислэгийн горимыг унтраана.
- [ ] Хэдэн секундын дараа дараалал хоосорч, өгөгдөл сервер рүү очно.
- [ ] **Давхардсан уулзалт үүсээгүй** эсэхийг шалгана.

## 3. Менежер болж шалгах (15 минут)

**И-мэйл шаардахгүй.** SQL Editor дээр:

```sql
UPDATE public.app_user
   SET role = 'manager'
 WHERE email = 'myagmarsuren.na@monos.mn';
```

Дараа нь компьютер дээрх Expo цонхон дээр **`r`** товч дарна (эсвэл утсаа
сэгсэрч → **Reload**). Апп дахин ачаална — **гарахгүй**, сесс хэвээрээ.

- [ ] Шинэ табууд гарч ирэв үү (Хяналтын самбар, Хүсэлтүүд, Эмч нар)?
- [ ] **Өнөөдөр / Долоо хоног / KPI табууд алга болсон** — энэ ЗӨВ. Менежерт
      өөрийн маршрут, өөрийн KPI байхгүй. Тиймээс §2-ын бүх зүйлийг эрхээ
      солихоос ӨМНӨ дуусгасан байх ёстой.
- [ ] Хяналтын самбар дээр багийн гүйцэтгэл харагдана.
- [ ] §2.6-д илгээсэн хүсэлт **Хүсэлтүүд** дотор байна.
- [ ] Түүнийг **зөвшөөрнө**.
- [ ] Төлөөлөгчийн долоо хоногийн төлөвлөгөөнд уулзалт **нэмж** үзнэ.
- [ ] Уулзалтыг өөр өдөр рүү **шилжүүлж** үзнэ.
- [ ] Экспорт (CSV) татаж үзнэ.

> Шалгах ёстой зүйл: менежер **анхны тайланг өөрчилж чадахгүй** байх ёстой.
> Зөвхөн нэмэлт тайлбар бичих боломжтой.

## 4. Администратор болж шалгах (15 минут)

```sql
UPDATE public.app_user
   SET role = 'administrator'
 WHERE email = 'myagmarsuren.na@monos.mn';
```

Дахин **`r`** дарж ачаална.

- [ ] Тохиргоо → **Хэрэглэгчийн удирдлага** нээгдэнэ.
- [ ] Шинэ хэрэглэгч үүсгэж үзнэ (жинхэнэ хүн биш, туршилтын нэр).
- [ ] Түүний эрх, менежерийг өөрчилнө.
- [ ] Идэвхгүй болгоод шалтгаан бичнэ.
- [ ] **Мастер өгөгдөл** → эмнэлэг, эмч нэмнэ / засна.
- [ ] Уулзалттай эмнэлгийг архивлах гэж үзнэ → **хориглох ёстой**.
- [ ] **Аудит** дэлгэц → өөрийн хийсэн бүх үйлдэл бичигдсэн байна.
- [ ] Аудитын бичлэгийг устгах / засах товч **байх ёсгүй**.

## 5. Дууссаны дараа

### 5.1 Аюулгүй байдлын өөрийн шалгалт

SQL Editor дээр:

```sql
SELECT * FROM public.fn_security_findings();
```

**0 мөр буцаах ёстой.** Мөр буцаавал надад бүтнээр нь илгээнэ үү.

### 5.2 Үрийн өгөгдлийг сэргээх

Туршилт дуусаад жинхэнэ ажилд шилжихдээ `rep01`-ийг буцааж өгнө:

```sql
UPDATE public.app_user
   SET email = 'rep01@monos.mn', role = 'representative'
 WHERE id = '00000000-0000-0000-0000-0000000000c1';
```

Мөн §0.2-т зөөсөн эмнэлгийн жинхэнэ координатыг сэргээхээ мартаж болохгүй.
Энэ бол `docs/PHASE-7-STATUS.md` §8-д бичсэн «эмнэлэг бүр дээр очиж координатыг
шалгах» ажлын нэг хэсэг.

---

## 6. Юуг надад мэдээлэх вэ

Аль ч алхам дээр гацвал дараах гурвыг илгээнэ үү:

1. **Аль дугаартай алхам** дээр гацсан (жишээ: §2.3).
2. Дэлгэц дээр гарсан **бүтэн бичвэр**, ялангуяа «Серверийн хариу» хэсэг.
3. Боломжтой бол **дэлгэцийн зураг**.

Ажиллаж байгаа зүйлээ ч хэлээрэй — юу нь бүтэн болсныг мэдэх нь юу нь эвдэрсэнийг
мэдэхтэй адил чухал.

---

## Хавсралт: и-мэйл шаардахгүй үйлдлүүд

| Хийх зүйл | Арга |
|---|---|
| Эрх солих | SQL `UPDATE app_user SET role = …` + `r` дарж ачаалах |
| Аппыг дахин ачаалах | Expo цонхонд `r`, эсвэл утсаа сэгсрээд Reload |
| Кодыг цэвэрлээд ачаалах | `npx.cmd expo start -c` |
| Нууц үг олгох | `npm.cmd run dev:set-password` |
| Өгөгдөл шалгах | Supabase → Table Editor |
| Нэвтрэх асуудал оношлох | `SELECT * FROM fn_diagnose_login('…');` |

| Нууц үг олгох / сэргээх | `npm.cmd run dev:set-password` + хэвлэсэн SQL мөр |
| Өөрийн нууц үг солих | Аппаас: Тохиргоо → Нууц үг солих |

**И-мэйл шаардах зүйл байхгүй.** Энэ нь өөрчлөлтийн гол ашиг.
